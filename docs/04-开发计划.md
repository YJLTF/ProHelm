# ProHelm（项舵）开发计划

> 版本：v0.1｜日期：2026-11-14｜配套：《05-团队组建方案》
> 范围：M1「核心可用版」（0~3 个月）的开发排期、任务拆解、工程规范与发布策略。

---

## 1. 目标与总览

**M1 出口标准**（对应《02-产品功能设计》第 7 章）：

- 5 分钟内创建一个带甘特图的项目，全程离线可用
- 任务/WBS/看板/里程碑可用，甘特图含依赖与关键路径
- 章程、干系人登记册、风险登记册三个核心工件可编辑
- AI（BYOK）可完成：项目上下文问答、章程生成、WBS 草稿生成
- 三平台（Win/mac/Linux）安装包产出 + 自动更新链路
- 内测 10 个真实用户跑通完整周期

**节奏**：6 个 Sprint × 2 周，2026-11-16 启动，2027-02-06 发布 0.1.0 alpha（春节前）。

```
S1      S2      S3      S4      S5      S6
骨架 →  WBS甘特 → 工件看板 → AI舵手 → 风险发布 → alpha
11/16   11/30   12/14   12/28   01/11   01/25   02/06 发布
```

> 春节缓冲：S6 结束恰逢春节假期前，若延期有 1 周缓冲窗口。

## 4. 工程规范

### 4.1 分支与提交

- **Trunk-based**：`main` 始终可构建可发布；功能开发走短生命周期分支 `feat/S2-cpm`，≤3 天合回
- **Conventional Commits**：`feat:`/`fix:`/`chore:`/`docs:`/`test:`，PR 标题同规范
- **PR 规则**：1 个 PR = 1 个 issue；AI 生成的代码必须经人工 review 后合并；核心算法（CPM/EVM/同步/加密）需双人 review
- **提交前检查**：`pnpm typecheck && pnpm build && cargo clippy --workspace && cargo test -p helm-core`

### 4.2 测试策略

| 层 | 要求 |
|---|---|
| Rust 单测 | 仓库层 CRUD 全覆盖；**算法（CPM/EVM/后续合并逻辑）100% 分支覆盖 + 黄金用例快照** |
| 集成测试 | helm-core 集成测试（in-memory DB 跑迁移+业务流） |
| 前端 | 纯逻辑函数 vitest 覆盖；组件测试仅覆盖复杂交互（甘特/看板） |
| E2E | 冒烟清单人工执行（三平台 × 新建项目到创建任务），S5 引入 WebDriver 自动冒烟 |

### 4.3 质量红线（DoD）

1. CI 全绿（typecheck + build + clippy -D warnings + tests）
2. 新功能带测试，核心算法带黄金用例
3. 无 `unwrap()` 在可失败的命令路径上（Rust 命令层一律 `Result`）
4. UI 文案统一中文，错误态有兜底文案
5. 离线可用性：断网状态下非 AI 功能不受影响

### 4.4 版本与发布

- 版本号：`0.x.y`（alpha 通道）→ 0.2.0（beta）→ 1.0.0（正式，M2 后）
- 通道：`alpha`（内测签名包）→ `beta`（公测）→ `stable`（自动更新推全量）
- 签名：Windows 代码签名证书 + macOS Developer ID（S5 前完成采购，时间风险项 ⚠️）
- 更新：tauri-updater + 公共更新清单（JSON）签名校验
